# Учебный проект по предметной области «Авиакомпания»

## Описание предметной области

Учебный проект сайта авиакомпании Nordline. Пользователь может найти рейс,
забронировать место, оплатить и получить билет. Администратор управляет
рейсами, самолётами и аэропортами через админ-панель.

### Users — пользователи сайта

Хранит учётные данные клиентов и администраторов.

- `id` — уникальный идентификатор (PK)
- `email` — почта, используется как логин (UNIQUE)
- `passwordHash` — хэш пароля (BCrypt/Argon2)
- `role` — роль: `client` или `admin`
- `fullName` — ФИО
- `phone` — телефон
- `createdAt` — дата регистрации

### Cities — города

Справочник городов, куда летает авиакомпания.

- `id` — идентификатор (PK)
- `name` — название города (Москва, Сочи)
- `country` — страна

Город вынесен отдельно от аэропорта, потому что в одном городе может быть
несколько аэропортов, а в уведомлениях и поиске пользователь видит именно
город, а не код аэропорта.

### Airports — аэропорты

Справочник аэропортов, привязанных к городам.

- `id` — идентификатор (PK)
- `code` — IATA-код: SVO, LED, AER (UNIQUE)
- `name` — полное название аэропорта
- `cityId` — ссылка на город (FK → Cities.id)

### Airplanes — самолёты

Справочник воздушных судов авиакомпании.

- `id` — идентификатор (PK)
- `model` — модель (Boeing 737-800, Airbus A320)
- `capacity` — вместимость

### Seats — места в самолёте

Сетка мест для конкретного самолёта. Заполняется при добавлении самолёта.

- `id` — идентификатор (PK)
- `airplaneId` — ссылка на самолёт (FK → Airplanes.id)
- `seatNumber` — номер места (12A, 12B)
- `seatClass` — класс: `Economy` или `Business`
- UNIQUE (`airplaneId`, `seatNumber`) — в одном самолёте нет двух одинаковых мест

### Flights — рейсы

Конкретные перелёты по расписанию.

- `id` — идентификатор (PK)
- `flightNumber` — номер рейса (SU-100)
- `departureAirportId` — аэропорт вылета (FK → Airports.id)
- `arrivalAirportId` — аэропорт прилёта (FK → Airports.id)
- `airplaneId` — назначенный самолёт (FK → Airplanes.id)
- `departureTime` — время вылета
- `arrivalTime` — время прилёта
- `status` — статус рейса: `scheduled`, `delayed`, `cancelled`, `completed`
- `basePrice` — базовая цена билета

### Bookings — бронирования

Объединяет данные о заказе: кто купил, на какой рейс, какое место,
на кого оформлен билет.

- `id` — идентификатор (PK)
- `userId` — покупатель (FK → Users.id)
- `flightId` — рейс (FK → Flights.id)
- `seatId` — выбранное место (FK → Seats.id)
- `bookingCode` — PNR-код брони (X7A9K2, UNIQUE)
- `passengerName` — ФИО пассажира (может отличаться от покупателя)
- `passengerPassport` — паспорт пассажира
- `price` — фактическая цена билета
- `status` — статус брони: `pending`, `paid`, `cancelled`
- `createdAt` — дата оформления
- UNIQUE (`flightId`, `seatId`) — защита от овербукинга на уровне БД

## Связи между сущностями

- **Cities → Airports** (1:M) — в одном городе может быть несколько аэропортов.
- **Airports → Flights** (1:M, дважды) — рейс имеет аэропорт вылета и аэропорт прилёта.
- **Airplanes → Seats** (1:M) — у каждого самолёта своя сетка мест.
- **Airplanes → Flights** (1:M) — один самолёт выполняет много рейсов.
- **Users → Bookings** (1:M) — один пользователь может оформить много броней.
- **Flights → Bookings** (1:M) — на один рейс продаётся много билетов.
- **Seats → Bookings** (1:M) — одно место может быть занято на разных рейсах,
  но не дважды на одном и том же (за это отвечает UNIQUE).

## Бизнес-правила

1. **Одно место на рейс продаётся один раз.** Гарантируется ограничением
   UNIQUE (`flightId`, `seatId`) в таблице `Bookings`. Если два пользователя
   одновременно попытаются купить одно место, БД отклонит вторую вставку.
2. **Пассажир может отличаться от покупателя.** Мама может купить билет
   ребёнку со своего аккаунта — в `Bookings` сохраняется ФИО и паспорт
   именно пассажира.
3. **Каждый рейс привязан к конкретному самолёту.** Модель самолёта определяет,
   какие места доступны для продажи на этот рейс.
4. **Поиск свободных мест на рейс** выполняется через LEFT JOIN между `Seats`
   (по `airplaneId` рейса) и `Bookings` (по `flightId`). Если для места нет
   записи в `Bookings` — оно свободно.
5. **История заказов пользователя** строится запросом к `Bookings` по `userId`
   с JOIN на `Flights`, `Airports` и `Cities` для отображения маршрута.
